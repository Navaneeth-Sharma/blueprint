Summary

Problem
todo list prints padded text with no escaping. A newline in a title forges a row (F2), ids of 1000 or more shift the columns (F3), and scripts have no supported way to read the list (F5).
Decision
Add --json to list only. It prints json.dumps(items): one compact line holding a JSON array of the store items as they are, with non-ASCII escaped. Plain output, add, done and corrupt-store handling stay as they are today.
Verify by
A new test_list_json unit test, then the real CLI on a scratch $TODO_FILE piped through jq for E1–E14 and C1–C8. That run includes an ASCII-only stdout and the pre-change commit 195c2d2.

Context

The plain format is an f-string with the title printed raw (F1), so text output can't be parsed safely: one title can pass for a finished item that doesn't exist (F2). The store already holds the shape scripts want, a JSON array of {id, title, done} (F4), but it is undocumented internal storage (F5). Today every version rejects --json with exit 2 (F6), which gives scripts a clean way to detect an old version. A corrupt store already ends with exit 1 and an empty stdout (F7), and the existing test harness captures stdout and the exit code, so a new test fits beside it (F8).

Decisions

  1. D1

    todo list --json prints json.dumps(items) followed by a newline and exits 0.

    The output is one compact line holding a JSON array, with non-ASCII escaped as \uXXXX. JSON escaping removes the forged-row problem (F2) and the column-width problem (F3). Pure-ASCII output also works when stdout isn't UTF-8 (E13). Rejected O2 because an empty list would print nothing, O3 because a second format is speculative, and O4 because tab-separated output brings back F2.

    Q1 → A · Q3 → A

  2. D2

    Items go from store.load() to json.dumps unchanged, with no per-field projection.

    add is the only thing that creates items, and it always writes exactly {id, title, done} (F4). So today the output is those three keys with their JSON types: id an integer, title a string, done a boolean. Consequence: any key the store gains later shows up in the output too (E14).

    Q2 → A · rejected Q2 B (build {id, title, done} per item)

  3. D3

    --json is an option of the list subparser only.

    todo --json list, add --json and done --json keep exiting 2 with unrecognized arguments. Every version before this change rejects list --json the same way (F6), so a script can tell an old version from a new one by the exit code.

    Q4 → A · rejected Q4 B and C, which would have added M2

  4. D4

    No change to store.py or to error handling.

    A zero-byte or corrupt store still prints a JSONDecodeError traceback on stderr, exits 1 and leaves stdout empty. save() stays non-atomic (F7). The only print runs after load() returns, so stdout holds either the whole array or nothing.

    Q5 → A

  5. D5

    Without --json, todo list output stays byte-for-byte the same, and the README documents list --json as the supported way for scripts to read the list.

    Existing users and test_add_list_done are unaffected (F1). With a documented flag, scripts stop reading ~/.todo.store directly (F5).

Consequences

Contract follows the store

Because of D2, the store's shape is now public. Adding a key is safe for jq users (E14); renaming or removing one breaks them. If the store ever gains an internal-only field, switch to building {id, title, done} per item (Q2 B) in the same change.

Not guarded

If the store's top level is valid JSON but not an array (hand-edited to {}), list --json prints {} with exit 0. Today plain list prints nothing for it, with exit 0. Accepted: only add writes the store (F4), and D4 keeps store validation out of scope.

Existing, not new

Scripts that poll list --json will run into the non-atomic save() race (E12) and the corrupt-store traceback (E11) more often than a person would. Both stay out of scope (Q5 A). If they show up, open a follow-up for an atomic write (temp file + os.replace).

Rollout

One commit. There is no migration, and the store format doesn't change. Existing users and scripts see no difference (D5).

Rollback

Revert the commit. Scripts that call list --json then get exit 2 with an empty stdout (E10), which they already have to handle for old versions.

Out of scope

--json on add and done, a global todo --json, JSON Lines, --format, a readable message for a corrupt store, and atomic saves.
