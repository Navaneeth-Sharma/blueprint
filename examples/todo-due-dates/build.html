Summary

Shipped
todo add <title> --due YYYY-MM-DD stores an optional ISO "due". todo list prints open items due today or earlier first, oldest first, with (due …, overdue); everything else keeps id order and gets (due …) if dated. Code changes are in todo/cli.py only (+25 lines), plus 3 tests and one README line. Not committed.
Verified
5/5 unit tests on Python 3.12 (with -W error) and 3.9. The real CLI was run against temp TODO_FILEs for every E# and C#: all pass. That includes old-vs-new output byte-identical on a pre-change store, rollback onto commit ad989f1, and the same file listed under UTC+14 and UTC−11.
Left
Nothing failed or untested. Two follow-ups for you to judge: the word “overdue” on the due day (Q1 → B, seen live in ev-list), and the commit.
